## 1. What this project actually is

- Astro 7, static output (`output: 'static'`), TypeScript strict.
- Dark-first "Nocturne" visual system. Design tokens (OKLCH-based) live in
  `src/styles/tokens.css` — never hardcode a raw color, always use a
  `var(--role)` token (`--bg`, `--text`, `--accent`, etc.). See
  `docs/THEMING.md` for the token model before changing colors.
- A hand-built, zero-dependency motion layer ported from Aceternity UI
  patterns, implemented as plain Astro components + CSS + a small
  `src/scripts/motion.ts` — **not** React/Framer Motion. Don't introduce a
  JS animation library; extend the existing compositor-only CSS approach.
- Contact form posts to Web3Forms using `PUBLIC_WEB3FORMS_KEY`, which is an
  environment/hosting secret — **never** hardcode it or commit it.
- Node version required: **22.12+** (CI uses Node 22).

## 4. Deployment — know this before touching anything CI/DNS-related

- Production: `https://suprabhat-dev.com`, served by **GitHub Pages**,
  deployed by `.github/workflows/deploy-pages.yml`, which triggers **only on
  push to `main`** (or manual `workflow_dispatch`). Nothing else deploys.
- Hostinger manages DNS pointing the custom domain at GitHub Pages — this is
  external to the repo; don't "fix" it speculatively.
- Netlify config (`netlify.toml`) exists in the repo but is **not** the
  active deploy path. Don't treat it as the source of truth for build/deploy
  behavior.
- `PUBLIC_WEB3FORMS_KEY` is injected as a CI secret at build time — never put
  a real key in code, `.env`, or a commit.

## 5. i18n / RTL rules

- Three locales: `en` (default, no prefix), `es` (`/es/...`), `ar`
  (`/ar/...`).
- Arabic pages render `<html dir="rtl">`; en/es render `dir="ltr"`. Any new
  UI must be checked in all three, and Arabic specifically needs a real RTL
  check (mirrored layout, correct text alignment, no leftover
  logical-property bugs like hardcoded `left`/`right` instead of
  `inline-start`/`inline-end`).
- New UI copy goes in `src/i18n/messages.ts` for all three locales together —
  never ship an English-only string and leave `es`/`ar` stale, and never
  invent an Arabic/Spanish translation you're not confident in — flag it for
  the human to confirm instead of guessing.
